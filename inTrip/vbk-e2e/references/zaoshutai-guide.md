# 造数台操作手册（zaoshutai / 指南针镜像平台）

> **造数台只产出成品**（有效 + 上线 + 可订）。中间态（刚建好、只亮「销售控制」「产品信息」、未上线）拿不到——改走产品列表页搜索 + 页面「复制」，见 [seed-data-sources.md](seed-data-sources.md)。本文只讲成品路径。

## 系统事实（2026-10 ~ 11 实测）

- 入口：`http://tour.product.tools.fws.qa.nt.ctripcorp.com/zaoshutai/`
- 前后端同源：`/api/**` 是后端接口，其余路径是页面路由；造数流式接口 `/api/tpldesk/duplicate/stream`（tpldesk 是业务模块前缀）
- 鉴权：内网 CAS。未登录时：页面路由 302 → `/accounts/login?next=…` → 再 302 到 CAS（`cas.intranet.fat358.qa.nt.ctripcorp.com`）；`/api/**` 返回 401 JSON `{"detail":"Not authenticated"}`
- 判定登录态失效最快的方法：URL 被重定向到 `/accounts/login` 或 CAS——**立即停下请人登录，绝不代填账号密码**；恢复登录后重新读页再续跑
- 后端是 Python ASGI（FastAPI/Starlette 系）服务

## 操作流程（browser-control 逐步）

1. 打开入口页，确认已登录（没有 CAS 跳转）；
2. 按意图 JSON 的 `filters` 逐个筛选项勾选（维度：形态、境内外×长短途、结构、资源、报价、渠道和站点、多语言、其它）。**先读一遍筛选项的真实枚举**，与 references/intent-schema.md 冲突时以页面为准，并回写该文件；
3. 模板列表里按筛选结果选模板（优先选标签齐全、最近更新的模板），记下模板 ID 与标题；
4. 点「一键造数」→ 弹窗里填副标题（**规范：`<releaseKey>-<序号>`，如 `XLSP-5126-01`**，这是后续回收/对账产品的唯一线索）→ 点「开始复制」；
5. 进入任务/详情页观察状态，进入 Step 4 轮询。

每一步操作前后各留一张截图（recordToReport 不适用此处，用 browser-control 的截图落本地，路径记入台账 notes）。

## 就绪判定（Step 4 规则）

状态链：

```text
已提交 → 新产品 ID 已生成 → 补齐各 Tab → 置有效 → 上线 → 检查班期可订 → 就绪
```

- ID 一般 30 秒左右生成；**此时页面明确提示「尚未就绪，请暂勿使用」——不许拿去写用例**；
- 三项全过才算就绪：**有效、上线、可订**；
- 轮询：每 20-30 秒读一次页面（刷新或重进详情页），总超时 5 分钟；
- 失败/超时：截图 + 台账记 failureClass=zaoshutai + 重试一次（重新走一键造数，副标题序号 +1）；再失败 → 停止上报；
- 就绪后记录 productId、三项状态、总耗时（上次实测：模板 8527535 → 8880320，142 秒）。

## 改版兜底

造数台 UI 改版导致定位失败时：换 2-3 种定位（文本、角色、坐标+邻近元素）仍失败 → 停止、截图上交，不强行点击、不盲猜。推动造数台提供接口（`/api/tpldesk/duplicate/stream`）是长期解，落地前先走浏览器。
