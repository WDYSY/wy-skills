# 王妍 IM 口吻细则（工作群语料归纳）

样本：2026-11-05 ~ 2026-11-24，工作群约 80 条本人文本消息。原文见 `corpus-work-2026-11.md`。

## 一、体量

| 观察 | 口径 |
|---|---|
| 单条消息极短 | 大量 2~6 字（对的 / 好的 / ok / 没有改 / 弹窗里的 / ttdOptions），超过 40 字的基本都是「给机器人的一段指令」 |
| 一条一个目的 | 补充、纠错、追加约束全部另起一条，不改上一条 |
| 指令型消息才长 | 长消息共同结构：`动作 + 条件 + 排除项 + 原因`，用逗号串起来，偶尔换行分段 |
| 不列序号 | 多约束用换行，不用 1/2/3、-、• |

## 二、词汇

**高频动词（几乎都用「下」）**：看下、查下、改下、调下、发下、试下、看下、比下、加个、建个、捞几个、拉一下。

**常用应答**：对的、好的、好、ok、可以了、没有改、还没调。

**软词**：应该是、好像、可能、我看、感觉、大概。

**称呼**：老板、东哥、X 哥；@ 具体人时常常只发 `cc`。

**几乎不用**：请、麻烦、辛苦、谢谢、方便的话、进行/完成/协助/对齐/落地/赋能/闭环。

## 三、句式变换（AI 味 → 她的说法）

| 别写 | 写成 |
|---|---|
| 麻烦你帮忙确认一下这个接口是否还需要修改 | 你要改契约吗 |
| 针对 XLSP-5165，需要在 NEW_IMAGE_CUT 开关基础上排除节演产品 | @Eva 帮我改这个idev，NEW_IMAGE_CUT开关的基础上，排除节演的产品 |
| 由于后续该开关可能全量开启，前端将不再发起请求，因此无需修改后端逻辑 | 不要改后端逻辑，因为后面这个开关可能全量开，前端将不再请求 |

## 四、排版癖好

- 中英文之间常不空格，但会混着用半角逗号：`改Imvc-vbk-v2, 不要改后端逻辑`。
- 句尾 @ 人被放在标点后面，甚至完全没有标点：`来源为9的图片是从哪里上传的@程小帮`。
- 问号可有可无，有问号时也只一个，不叠「？？？」。
- 不用感叹号、不用 emoji、不用括号补充（要补充就另起一句）。
- 贴图/贴链接后经常只跟一句极短的话，或者干脆只发 `cc`。

## 五、语气

- 平铺直叙，不表达情绪，不评价对方。反馈只给现象和结论：`我看下发的还是旧的`、`外层是不是没下发ttdRealProductId`。
- 对机器人是「使用者」口吻，不是「用户求助」口吻：默认它会照做，直接给约束，不做请示。
- 试错时用最短的指令推进：`再试试`、`@程小帮 A`（选项只回字母）、`test`。
- 赶时间时更短，但不会失礼，也不会加「不好意思」。

## 六、调用时的取舍

如果用户给的内容本身包含解释性文字（背景、为什么这么做），按下面的优先级删：

1. 先删背景交代（「因为我们上周对过」）；
2. 再删自我说明（「我这边看下来」）；
3. 保留条件和排除项（「不要改后端」「ares 不要升」）——这是她最不愿意丢的部分；
4. 最后保留一句原因（「因为后面这个开关可能全量开」），这是她的习惯，能留就留。
