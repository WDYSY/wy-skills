# wy-msg · 用王妍的身份发飞书消息

王妍点名收件人 + 内容，**非本人收件人先预览再发**（见第 4 步），本人直接发；只有收件人有歧义、或内容涉及对外承诺/数字时才多问。

## 口径（王妍 2026-11-06 确认，别再问）

| 项 | 默认 | 说明 |
|---|---|---|
| 身份 | **王妍本人**（`--as user`） | 只有她明确说「用机器人/程小帮身份发」才用 `--as bot` |
| 预览 | **发给别人之前先预览** | 收件人不是王妍本人时，把标题、字段、代码块、按钮和链接摆给她看（Markdown 复现，不贴原始 JSON），她说发才发。**发给王妍本人一律跳过预览** |
| 代发注明 | **一律不加** | 不写「程小帮代发」「触发人：王妍」、不署名、不附时间戳、不加免责行。正文只有她要说的内容 |
| 形态 | **优先卡片**（`--msg-type interactive`） | 只有明确要「原话照发/一句话/口头转达」时才用 `--msg-type text` |
| 收件人 | 只发她点名的对象 | 不猜、不扩散、不顺手抄送。找不到人或群就停下来问，禁止换成同名的别人 |
| 内容 | 她给的原话 | 不美化、缩写、改语气、加客套 |
| 称呼 | **正文不写收件人姓名** | 不写「王妍，……」「XX 你好」，直接说事；要提醒到人就靠群里的 @ 或单聊本身的收件人（王妍 2026-11-06 要求） |

## 第 1 步：解析收件人

**人**：`lark-cli contact +search-user --query <名字> --as user --json`

- 取 `p2p_chat_id` 直接发；没有单聊会话时用 `open_id` 走 `--user-id`（飞书会自动开会话）。
- 用 `localized_name` + `department` 核对是不是同一个人；重名或命中多个 → 列给王妍选，不要自己挑。
- 王妍本人 open_id：`ou_c4adae1a03c2ef1b6f50404e6d643472`。

**群**：`lark-cli im +chat-search --query <群名> --as user --json`

- 取 `chat_id`（`oc_xxx`）。群名搜不到时去掉后缀再搜（「小兵claw嘎群」实际叫「小兵claw嘎」）。
- 命中多个群 → 列名字给王妍选。
- 要 @ 群里的人，需要那个人的 `open_id`（`contact +search-user` 取）。

**已经知道 chat_id 就别再搜**，直接发。

## 第 2 步：选形态

| 内容 | 形态 |
|---|---|
| 多个字段 / 链接 / 状态 / 需要一眼分清 | 卡片（默认） |
| 一句话、原话照发 | `--msg-type text` |
| 带文件或图 | `--file` / `--image`，卡片里再补一句说明 |
| 同一内容发多人多群 | 每人/每群各发一条，各自记 message_id；不要群发工具、不要拼进一个会话 |

## 第 3 步：拼卡片（硬规则）

**先选结构，选错代码块就变成一行反引号**：

| 要什么 | 用哪个 | 关键差异 |
|---|---|---|
| 代码块 / 富文本排版（默认） | **卡片 2.0**：`"schema":"2.0"` + `body.elements` 里的 `markdown` 元素 | 按钮用 `behaviors: [{type: "open_url", default_url, pc_url}]` |
| 只有字段 + 按钮，不涉代码块 | 卡片 1.0：`config` + `header` + `elements` 的 `div`+`lark_md` | 按钮用 `"url": "..."` |

- **1.0 的 `lark_md` 不解析 ``` 代码块**（实测会把反引号和换行原样显示，王妍 2026-11-06 截图确认）。要代码块就必须用 2.0 的 `markdown` 元素。
- 2.0 在**旧版飞书网页客户端**可能显示「当前版本不支持查看」，渲染以桌面端/手机端为准；不确定要不要兼容旧网页时就问一句。
- 颜色口径：正常/完成 `green`，提醒/未达成 `yellow`，失败 `red`，一般通知 `blue`。

### 版式规范（王妍 2026-11-06 定稿，照抄骨架）

1. **标题**：`<emoji> <事情> · <状态>`，12 字内。例：`✈️ 问题已修复 · 可查看`、`🚀 应用发布 · 开始`。
2. **正文用字段表，不写整段话**：每行一个 `column_set`，左列固定 `120px` 放「emoji + 灰字标签」，右列 `weighted` 放值。不要写「王妍，……」这种称呼，也不要寒暄、总结句、「点击本通知可跳转查看」之类废话。
3. 标签一律 `<font color='grey'>📄 页面</font>` 这种灰字；值是纯文本，不加粗、不加标签。
4. 需要留完整地址才加代码块（灰标签 + 代码块），**代码块没有复制图标**，别写「点右上角复制」不存在的话。
5. **按钮整宽**：`"width": "fill"`，主操作 `"type": "default"`（带边框），文案统一「查看详情」「打开页面」这类 4 字内动词，**按钮上不放链接文字**，跳转写在 `behaviors[].open_url`。多操作时并排放 `column_set` 两个 `weighted` 列，不要竖着堆两个整宽按钮。
6. `hr` 把内容区和按钮区隔开。
7. 群里 @ 人：正文用 `<at id=ou_xxx></at>`；text 消息用 `<at user_id="ou_xxx">名字</at>`。
8. 一张卡只讲一件事，多个对象就多张卡。
9. `--content` **不吃 `@文件名`**（会报 not valid JSON），必须内联 JSON 字符串；外层用单引号，内部双引号。

模板见 `references/cards.md`，改内容和字段，别改骨架。

## 第 4 步：发之前核对

**先预览，再发（非本人收件人）**。收件人不是王妍本人时，把将要发送的内容摆给她看，等她点头：

- 卡片：列标题、每行字段（标签 + 值）、代码块全文、表格、按钮文案和链接。卡片 2.0 不方便人读 JSON，**不要贴原始 JSON**，用同构的 Markdown 复现一遍即可。
- 文本：直接贴原文。
- 她说「改……」→ 改完再预览一次；她说「发/可以」→ 执行发送。
- **发给王妍本人的一律跳过预览，直接发。**

逐项核对：

1. 收件人：名字/群名 + chat_id 对不对（群里发的所有人都看得见）。
2. 正文：是否是王妍说的那件事，数字/链接/时间有没有抄错。
3. 形态：卡片以下发的命令和 JSON 有没有引号、字段缺漏（发出去改不了，只能再发一条）。

内容里出现「已修复/已上线/已完成」这类对外承诺，必须来源可查（她自己说的、或你在同一会话里确认过的事实）。

## 第 5 步：发送

```bash
# 卡片到群（2.0 + markdown，默认版式）
lark-cli im +messages-send --chat-id <oc_xxx> --msg-type interactive \
  --content '{"schema":"2.0","config":{"wide_screen_mode":true},"header":{...},"body":{"elements":[...]}}' \
  --as user

# 卡片给个人
lark-cli im +messages-send --user-id <ou_xxx> --msg-type interactive --content '{...}' --as user

# 一句话原话
lark-cli im +messages-send --chat-id <oc_xxx> --msg-type text \
  --content '{"text":"<原话>"}' --as user
```

- `--as user` 是默认，**不要因为习惯写成 `--as bot`**。
- 需要防重复发送时加 `--idempotency-key`。
- 返回 `ok: true` + `message_id` + `chat_id` 才算发成功；失败按错误码处理（`230026` 无权限撤回、`im:chat:read` 不足 → 换搜群方式），不要静默重试发出第二条。

## 第 6 步：回报

一条简短结果，包含：

- 发给了谁/哪个群（chat_id）
- 形态（卡片/文本）与 message_id、时间
- 正文关键内容一行摘要
- 没做到的（收件人没找到、只发了部分人、卡片发出去想改）明确写出来，不要说「已通知」含糊过关

## 撤回

- 以王妍身份发的消息，她本人可以撤回：`lark-cli im messages delete --message-id <om_xxx> --yes`（**高风险操作，先征得她同意**）。
- 以 bot 身份发的消息基本撤不回（普通成员撤不了别人的消息，且 lark-cli 不许 bot 调 delete），所以 bot 身份只在明确要求时用，且发前核对。

| 王妍说 | 动作 |

| 「发给郑潍雯：你最好真的是要吃饭」 | 搜人 → 一句话，`--msg-type text` → 正文就是原话，不加任何注明 |
| 「在商品后台小组群说一下问题已修复，链接 xxx」 | 搜群 → 绿色卡片：标题「问题已修复」+ 字段正文（不写谁的名字）+ 「查看页面」按钮 + 代码块留完整地址 |
