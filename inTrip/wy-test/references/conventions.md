# 用例条目模板与输出约定

## 输出目录

```
<wy-test 技能目录>/output/<YYYY-MM-DD>-<page>/
├── 用例-<同学甲>.md
├── 用例-<同学乙>.md
├── 用例-程小帮补充.md
└── index.md
```

> 产物**只放在技能目录**（`wy-test/output/`），不要写进业务仓库的 `.tmp/` —— 仓库只放代码。

`<page>` 用 `references/pages.md` 的页面 key（如 `product-baseinfo` / `tripProduct`）。

## 单条用例模板（三份统一，便于 index 去重）

```markdown
### TC-<page缩写>-<三位序号> <场景名>
- **优先级**：P0 / P1 / P2
- **来源**：XLSP-4993（韩瑞莉）｜ C-01（程小帮推导：`ServicePersonnelSection.tsx:257`）
- **前置数据**：产品 8837041（`select * from prd_product_service_personnel_3 where product_id=8837041`）
- **步骤**：
  1. 打开 <URL>
  2. <操作>
- **预期**：<可判定结果：具体文案 / 置灰状态 / 保存是否被拦 / 落库变化>
- **依据**：bug XLSP-4993 ｜ 代码 `shared/servicePersonnel/index.ts:436` ｜ 表 `prd_segment_resource_group`
```

## 优先级口径

| 级别 | 判定 |
|---|---|
| P0 | 死锁类（区块不可编辑但保存被拦）、数据落库错误、二期主链路阻断 |
| P1 | 与 PRD 口径不一致（置灰/拦截/联动逻辑错）、跨版本（简版/复杂版）表现不一致 |
| P2 | 文案、提示、样式、极端存量数据 |

## 来源写法（必须可追溯）

| 来源类型 | 写法 | 要求 |
|---|---|---|
| 历史 bug | `XLSP-xxxx（提交人）` | 必须能在 `kb/bugs/*.json` 里查到 |
| 程小帮推导 | `C-xx（程小帮推导：<file:line 或 表.字段>）` | 必须给出代码行或表字段 |

## index.md 结构

1. **结论**：本次改动涉及 N 个页面 / M 个校验分支；历史相关 bug X 条（同学A a 条、同学B b 条）；新增补充场景 c 条
2. **交集必测**（表格：场景 / 出现在哪几份 / 优先级）
3. **各份差异说明**（为什么 A 有而 B 没有）
4. **待产品拍板**（当前前端未实现或口径冲突的点，单列）

## 禁止

- 不要为凑数编造"历史出过"的场景（来源必须能查 key）
- 预期不要写"正常显示""符合预期"这类不可判定的话，要写具体文案/状态/是否拦截
- 同一条用例不要在三份里重复展开：index 里指路即可
