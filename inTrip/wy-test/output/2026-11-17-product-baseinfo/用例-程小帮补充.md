## C-01 只读判定与跳过校验"同源"（本轮重构点）
- **优先级**：P0 ｜ **来源**：C（`shared/servicePersonnel/index.ts` 的 `getServicePersonnelAccess`）
- **前置数据**：省钱 **8845992**、包装 **6785744**、预览态（任意产品点「预览」）
- **步骤**：三种产品分别打开 → 看区块是否置灰 → 直接保存
- **预期**：三者都**置灰 + 保存不校验**；`reason` 分别为 `lowPrice` / `packaged` / `viewMask`
- **依据**：`getServicePersonnelAccess({isViewMask,isPackagedProduct,isLowPriceProduct}) → {readOnly, skipValidation}`
- **为什么要测**：以前"页面置灰"和"保存豁免"是两处代码，容易只改一边 → 死锁（XLSP-5014 即此类）

## C-02 资源组删除后：语言放开 + 多语言保存拦截（双层）
- **优先级**：P0 ｜ **来源**：C（`getLanguageSyncState`）
- **前置数据**：**8837041**（导游组已删，导游 `10,3`）；简版 **8835506**
- **预期**：① 下拉**可编辑**（不是只放开就完事）；② 直接保存被拦「只能选择一个」；③ 改成单个后可保存
- **依据**：`state==='unknown'` → 不置灰；`validateServicePersonnelList` 对 `unknown + 多语言` 拦截
- **与 XLSP-4993 的差别**：她只验收了"可编辑"，没验收"必须改单个才能存"

## C-03 资源组在、但组语言与人员语言不同 → 可编辑 + 拦截
- **优先级**：P0 ｜ **来源**：C
- **前置数据**：**8759715**（用车组 157032 + 导游组 157046；司兼导 `4,9,3`）、**8759195**（用车组 157032；司机 `16,8,10,3`）
- **步骤**：打开页面看是否置灰；再点保存
- **预期**：不置灰（`different`）；多语言状态下保存被拦
- **依据**：`synced/different/unknown` 三态；只有 `synced` 置灰

## C-04 资源组在、语言一致 → 置灰且可保存（简版唯一 3 个样本）
- **优先级**：P0 ｜ **来源**：C
- **前置数据**：**8412829**（导游组 89545）、**2145309888**（导游组 89545）、**2145293283**（导游组 103909，单语言 `3`）
- **预期**：一致 → 置灰；多语言按多选只读展示；保存**不**被拦
- **依据**：`synced`
- **注意**：这是简版仅有的"有人员 + 有资源组"样本，测完别改它们的资源组

## C-05 拼小团 + 多语言（PRD 1.1.3 规则3，前端未实现）
- **优先级**：P1 ｜ **来源**：C（PRD 缺口）
- **前置数据**：**7702451**、**7731939**、**2145321331**（6206）、**6654515**、**6664259**（30804）——均 `isSmallGroup='T'` 且当前无服务人员，需现场加

## C-06 直连产品：服务人员允许为空（PRD 1.1.4，前端会误拦）
- **优先级**：P1 ｜ **来源**：C（PRD 缺口）
- **前置数据**：**2272427**、**2272651**（30804，`ConnectionVendorID=12`，全库仅这 2 个）
- **步骤**：直连产品不配服务人员 → 保存

## C-07 子产品：是否与母产品共用服务人员清单
- **优先级**：P1 ｜ **来源**：C（未确认）
- **前置数据**：**5541379**、**4142355**（6206）、**5692099**、**5692563**（30804，`prd_product_children.is_active='T'`）
- **步骤**：在母产品配服务人员 → 打开子产品看是否继承、能否编辑；子产品保存是否被必填拦

## C-11 契约来源防回归：语言字段必须读 `meta` / `other`
- **优先级**：P1 ｜ **来源**：C（后端契约曾写错成 `baseInfo.addonGuideServiceLanguage`）
- **步骤**：抓 `getProductBaseInfo` 响应，确认 `meta.guideGroupServiceLanguage` / `meta.carGroupServiceLanguage`（复杂版）、`other.*`（简版）有值，且页面置灰依赖于它们
- **预期**：前端读 meta/other；若后端改回 baseInfo，前端会全量 unknown → 多语言产品保存全被拦（属可观测异常）
- **依据**：`BaseInfo.tsx` / `ServicePersonnel/index.tsx` 的取值分支（含大小写兜底）

## C-12 CN 锁定角色 + 存量多语言（组合态）
