# wy-ask · 学会提问

把对话里的结论拖到 11 个关键问题前面过一遍，输出**少数几个真正能改变结论的问题**，每条都带"对方答上来才算过关"的标准。不是复述书，是拿来用。

## 先读哪个文件

- `references/question-bank.md` —— 11 问的触发信号、可直接照发的问题原话、过关标准、常见糊弄回答。**每次都要读**，提问的弹药全在这里。
- `references/fallacies.md` —— 13 种谬误与三类根因。扫 LOGIC 那一层时读，避免自己提问时也踩。

## 核心原则

1. **只审结论，不审立场。** 靶心是"对方希望你接受的那句话"，不是他的身份、动机或语气。
2. **强势批判，把自己也放进去。** 如果这段对话里我（agent）给过方案、下过判断，它同样要过一遍。只挑别人毛病是弱势批判性思维。
3. **少而狠。** 默认 6~9 条，硬上限 12 条。按"能多大程度动摇结论"排序，不是按 11 问顺序。
4. **每条问题必须挂原文。** 引用对话里的那句话、那个数字、那个词。写"数据可靠吗"是废话，写"你说的 63% 覆盖率，分母是全部 SKU 还是在售 SKU"才是问题。
5. **答不上来的才是好问题。** 每条标注"对话现状"：是没提、还是只给了模糊说法、还是给了但来源不明。这是清单的价值所在。
6. **提问是手段，找真相是目的。** 不抓稻草人、不揣测动机、不为了赢。清单最后要能回答"什么样的情况下这个结论其实是对的"。

## 执行流程

### Step 0 · 认清场景（10 秒，别跳过）

先判断这次要审的是什么，场景决定优先扫哪几层：

| 场景 | 典型说法 | 优先扫 |
|---|---|---|
| 方案 / 技术选型 / 排期 | "我打算用 A 方案""两周能做完" | 假设、替代原因、省略信息、备选结论 |
| 需求 / PRD / 规则设计 | "加个开关就行""用户肯定需要" | 论题是否明确、价值观假设、证据来源 |
| 数据 / 汇报 / 复盘 | "转化涨了 30%""失败是因为 X" | 数据欺骗性、替代原因、省略信息 |
| 别人发来的文章 / 演讲 / 广告 | "转给你看看""这个说法很对" | 全套，重点词义、谬误、证据效力 |
| 我自己的判断 / agent 给的建议 | "结论是……""建议这样做" | 强势批判：假设、一厢情愿、省略的反面 |

### Step 1 · 锁定靶心

从上下文里找出结论。判定标准：

- **结论 = 需要理由支撑、可以被反驳的主张。** 事实陈述、操作指令、个人偏好都不是结论。
  - 不是结论："周三下午开会。"（安排）
  - 不是结论："我不喜欢这个交互。"（偏好）
  - 是结论："这个交互不该做，因为用户根本不会用。"（主张）
- 有多个结论时，按 **决策影响 × 争议度** 选 1~2 个主靶，其余列进"次级靶子"一句话带过。
- 找不到明确结论（对话只是在讨论执行细节）→ 把靶心降到"这个方案的前提"，并在输出里说明"没找到可反驳的结论，我审的是它的隐含前提"。
- 结论必须**原文引用**，不改写。改写会把你的理解混进靶子里。

### Step 2 · 重建论证链

用一句话把结构摆出来，缺哪环，问题就落在哪环：

```
结论 ← 理由1、理由2 … ← 假设（价值观 / 描述性） ← 证据（直觉 / 经历 / 案例 / 证词 / 专家 / 研究 / 数据 / 类比）
```

对话里常见的三种残缺：

- 只有结论，没有理由 → 第一问就是"为什么"。
- 有理由，但理由本身是另一个未证明的结论 → 追问理由的理由。
- 理由齐全，但理由推不出结论 → 找缺失的假设（第 4 问）。

### Step 3 · 按三层扫描

照你笔记里的骨架，从微观到宏观：

1. **论点层**（Q1、Q2）：论题是描述性还是规定性？结论和理由分得清吗？
2. **微观检验**（Q3、Q4）：关键词有没有歧义？结论和理由之间靠什么假设搭桥？
   - 规定性问题（该不该、好不好）→ 必挖价值观假设。
   - 描述性问题（是什么、会不会）→ 必挖描述性假设（过去成立≠将来成立；我的情况≈你的情况；好处只有这一条路能拿到）。
3. **宏观检验**：
   - **真不真**：Q6 证据效力、Q8 数据欺骗性、Q7 替代原因。
   - **全不全**：Q9 省略信息（反面证据、失败案例、成本与负面效果、利益相关方、长期效果）。
   - **通不通**：Q5 谬误（见 `references/fallacies.md`）。
4. **结论层**（Q10）：是不是二分法？能不能加条件句？换成"要解决这个问题该怎么做"能得出什么别的结论？

**不要 11 问全上。** 一篇文章里同时命中的通常只有 3~5 层，其余层写了也是凑数。

### Step 4 · 出清单

每条问题四件套，缺一不可：

1. **锚点**：引用原文那句话 / 数字 / 词。
2. **问题原话**：能直接复制发给对方的问句，不用改。
3. **为什么卡在这里**：一句话说清它卡住的是哪一环（词义 / 假设 / 证据 / 遗漏 / 谬误 / 结论）。
4. **过关标准**：对方给出什么样的回答，这条才算过；以及什么样的回答是糊弄。

分级：

- **必须先答**（≤4 条）：不回答就没法判断结论成立与否。
- **值得追问**（≤5 条）：会削弱结论强度，但不至于推翻。
- **可选**（≤3 条）：让论证更完整、更好说服第三个人。

### Step 5 · 反向自检（强势批判的关键一步）

清单写完，逐条问自己：

- 这条问题里有没有我自己的谬误？尤其：把"我不同意"包装成"逻辑有问题"、揣测对方动机（诉诸动机）、要求对方给出完美证据（苛求完美）、曲解对方观点再打（稻草人）。
- 有没有哪条是我不敢问的？通常是会推翻我自己方案的那条——它才是第一条。
- 清单里有没有"通用问题"？有就删，或者换成带原话的具体版本。
- 我给出的"备选结论"，是不是真的能从现有理由推出来，而不是我另起炉灶？

### Step 6 · 输出

默认直接在对话里给清单，不落文件。用户要存档、要发群里、要做成文档时再落盘（发飞书用 `wy-msg`，写文档用 `wy-doc`）。

用户调整强度时：

- "快筛 / 就挑最狠的" → 3~5 条，只留"必须先答"。
- "标准" → 默认 6~9 条。
- "全套 / 往死里问" → 12 条 + 全部四个分组 + 备选结论展开。

## 输出骨架

```markdown
## 靶心
- **主张（原文）**：「……」
- **论题类型**：描述性 / 规定性
- **现在的理由**：…
- **没明说的假设**：…（价值观：… / 描述性：…）
- **初判**：暂时成立 / 证据不足 / 有硬伤（一句话，不展开）

## 必须先答
1. **【词义】「……」里说的"X"具体指什么？**
   - 卡在：关键词语歧义，X 至少有 A、B 两种解读，结论在两种解读下完全不同。
   - 答上来才算过关：口径 + 边界 + 谁定的。
   - 对话现状：没提 / 只有"大概差不多"这种说法。

（2~4 条，同上格式）

## 值得追问
（逐条列出问题原话 + 一句话为什么问，不必都写四件套）

## 可选
（同上，最多 3 条）

## 备选结论
- 如果 A（某个假设）成立 → 结论应改为 …
- 如果 B（某个被省略的因素）是主因 → 该做的事是 …

## 提问策略
- 先认同哪部分（哪句是真的站得住，先说出来）
- 对谁提、什么时候提（会上 / 私下 / 补数据后再提）
- 哪些问题**先别问**（对方答不了、时间成本不划算、问了只会激化）

## 自检
- 清单里我删掉的：…（原本想问但属于苛求完美 / 稻草人的那条）
- 最该问但最不想问的：…
```

## 提问纪律（第 11 问）

书里那句"也许我们根本就问错了问题"同样适用于你自己——提得对不如提得是时候。

- **先给台阶再提问。** 先说对方哪一点成立，再问缺口。一上来就质疑结论，触发的是防御，不是思考。
- **一次只问一层。** 同一句话里塞三个问题，对方只会回答最容易的那个。
- **对方答不上时停下来。** 那是信息缺口，不是辩论赛得分点；记下来，问"这个数据谁有"。
- **找共同基础。** 先确认双方都认的结论或价值观，再定位分歧原点。
- **问自己"我有没有可能是错的"。** 每轮清单至少留一条是审自己的。
- **别在不值得的问题上用力。** 结论无关决策、成本远大于收益、对方无决策权时，提问就是消耗。

## 反模式

- 把 11 个问题当检查表逐条列一遍——这是书里批评的"在错的时间提问"。
- 只列问题不给过关标准——对方随便答一句你也没法判断。
- 只说"数据不严谨""论证不充分"——这是评价，不是问题。
- 只审别人不审自己，把清单写成辩护词。
- 为了显得犀利，挑语气、措辞、个例错误，放过真正的推理断层。

## 边界

- 只在用户要"审 / 质疑 / 挑问题 / 批判性看"时启动；用户只是要方案、要结论时不要主动抬杠。
- 不编造证据和数据。对话里没有的信息一律标"需对方补充"，不替他补。
- 结论涉及事实核查且可查证时，可以顺手查证并注明来源；查不到就写明"未核实"。
- 输出里的药品剂量、法律条款、财务数字这类高风险结论，明确提示需要专业复核，不靠逻辑自洽下判断。
