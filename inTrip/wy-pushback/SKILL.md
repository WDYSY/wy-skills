# wy-pushback · 排期冲突时的回复话术

场景是**别人单方面改了我的时间**：产品把提测日提前、测试按后端估的工时把前端排上线、项目在群里通知式安排、已经发到环境了让你"调下"。

输出**一句能直接粘到飞书发出去的话**，不是分析报告。原则来自郑潍雯在「小兵claw嘎」群两次手把手教的原话（2026-09-07、2026-11-25），逐条见 `references/corpus-schedule-conflicts.md`。

## 一、先判断是哪一档

| 现象 | 档位 | 默认动作 |
|---|---|---|
| 群里说提测/上线时间改了，没改排期文档 | A 时间被提前 | 先要文档，一句话打回 |
| 工时被压缩、被按别人估的时间排 | B 工时被代排 | 否认这个时间，指出没确认过 |
| 已经发到 fat/环境，让你"可以调了" | C 既成事实 | 报实际工时，给不可能的结论 |
| 只是提前打招呼、还没定 | D 事前 | 拉群对双方工时 |

一档一句话就够，不用把 A~D 全说一遍。

## 二、四条硬原则

1. **认文档，不认口头**。排期文档写 12/07，谁来口头提前都不算，先让他改文档。
   > 以排期文档为准哈
2. **拿工时算账，不吵架**。不解释辛苦、不谈感受，只报「现在到哪 + 实际开发工时 + 结论」。
   > 现在还没开发，按实际开发工时 7号提测不可能
3. **责任归位，谁欠谁补**。没跟我确认过的排期不成立；从我这里挤出来的时间不背。
   > 我们还没回，这边就排上了，没人跟我们前端确认。那你要发，你自己后端发，前端发不了
4. **要提前可以，去别处 PK**。给替代路径而不是给情绪，让对方知道成本不在我身上。
   > 我这里排好了的，要提前你得和别人产品项目去PK

补充：**能群里说就群里说**（"或者你就群里说"），结论留在有记录的地方，不留在私聊里。

## 三、话术库（按档位取，原话）

**A · 时间被单方面提前**

- 最短、最常用：`以排期文档为准哈`
- 要顶回去但留面子：`我这里排好了的，要提前你得和别人产品项目去PK`
- 对方说"大家都提前了"：`没人跟我沟通，这个时间我不太认可`

**B · 工时被代排 / 被压缩**

- `没人跟我沟通，这个时间我不太认可`
- `我们还没回，这边就排上了，没人跟我们前端确认。那你要发，你自己后端发，前端发不了`
- 前置预防（事前阶段用）：`我们每次都会拉个群，确认下双方工时`

**C · 已经发了环境，让你开始调**

- `现在还没开发，按实际开发工时 7号提测不可能`
- 变体：`今天明天还在别的项目上，周五进还差不多`

**D · 只是打招呼 / 还没定**

- `排期沟通一下`
- `拉个群确认下双方工时`

## 四、发之前先问清四件事

缺一件就别写死日期，宁可先问用户：

1. 排期文档上现在写的日期是几号？（A 档的弹药）
2. 实际还需要几天？（C 档的弹药，用自己填的工时，不用别人代估的）
3. 谁改的、在哪改的——文档、群公告、还是口头？（决定要不要"以文档为准"）
4. 用户手上有没有别的项目占着？（决定能不能说"周五进还差不多"）

## 五、口气（和 wy-oral 一致）

- 1~2 句，能 4 个字说完就 4 个字。**不写小作文**。
- 不用感叹号、不用"麻烦/辛苦/抱歉打扰"、不铺"针对这个问题我想沟通一下"。
- 数字和日期直接写：7号、12/07、4天。不写"大约一周左右"。
- 不阴阳、不点名骂人。"骚操作""戏精"这种只在姐妹群说，进工作群就换成事实。
- 不主动给退路：不写"我尽量""加班赶一下"，除非用户明说可以让。
- 对方是产品还是后端决定措辞：对产品讲**文档和优先级**（A），对后端/测试讲**工时和谁发**（B/C）。

## 六、输出格式

1. 第一行给判断：`这档是 A（时间被提前）`，加一句还需要补的事实（如果有）。
2. 代码块给**一条**可直接发的话（默认最短档）。
3. 用户情况明显更硬、或对方已经在群里施压时，再给一条"升级版"，标明用在哪。
4. 不在话术里补占位符；缺的日期放在代码块下方一行说明。

## 七、自检

- 有没有超过两句？超了砍。
- 说的是文档、工时、责任里的哪一条？一条都没落到事实就重写。
- 有没有替用户答应下来（"可以"、"我赶一下"）？有就删。
- 日期和工时是不是用户亲口给的？不是就留空去问。
- 有没有感叹号、情绪词、敬语堆叠？有就删。
