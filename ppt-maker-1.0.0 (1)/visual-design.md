# 视觉设计原则与截图检查

> ⚠️ **LibreOffice 渲染警告**:emoji 和中文字体在 `soffice` 自检里**不准**(emoji 退化为基本字符,中文字体可能退化为系统默认)。**以 PowerPoint 截图为准**。检查 LibreOffice 截图时,只看排版/对齐/元素位置,**不要**根据字体细节判断 bug。

---

## 内容自检清单(SKL-10 新增,在出 design.md 之前必跑一遍)

### 概念澄清三问

每页强制回答:
1. **它是什么?** — 一句话定义
2. **它解决什么问题?** — 一句话因果
3. **我们目前在哪个阶段?** — 现状/未来

任何一问答不出来或模糊 → **停下问用户**,不要硬画。

### 名词关系画法

如果一页含有 **2+ 关键名词**,必须先画出关系:**并列 / 包含 / 正交 / 因果**。画不出来 = 概念没理清 = 停下问用户。

### CTO 模式 slide 文本黑名单

适用于受众是 CTO / 管理层的场合,作用于**所有 slide 文本**(不只是演讲稿)。

| ❌ 黑名单 | ✅ 推荐 |
|---|---|
| 代词开头("我们/你/大家...") | 名词短语开头 |
| 疑问句标题("...是什么?""怎么做?") | 陈述名词短语 |
| 口语句式("做得怎么样""为啥这么做") | 正式书面 |
| 动词短语标题("提升 X""优化 Y") | 名词短语标题("X 优化方案") |

**推荐范式**:**名词短语 + 副标题**(例:"规则体系 · 70+ 条 9 大类")。

### 数据 4 要素核对

任何要进 slide 的数字,**必须能回答 4 个问题**:

| 数值 | 时间口径 | 测量定义 | 性质(现状/目标) |
|---|---|---|---|

口径不全的数字宁缺勿滥。CTO 材料里最危险的就是放一个会被追问而答不上的数字。

### 凑数检测

每个新加的元素必须答:**"如果删掉这条信息,听众会少理解什么?"**

答不上来就别加。视觉不平衡的解法不一定是加内容。

### 对照锚点对齐

写"vs 别人 / 比某个东西好"类的论点前,**先问用户**:"这页的对照对象是 [A] 还是 [B] 还是 [C]?"

按叙事目的选(讲提效就对照人工,讲技术领先才对照同类工具)——不要默认对照"行业最先进方案"。

### 并列元素一致性

同组卡片/列表的:
- 标题字段类型必须一致(都是定位 / 都是数据 / 都是动作,不混)
- 字号、颜色、对齐方式必须一致

### 术语分级

按目标读者层级,只用对应级别的术语:

- **CTO 可懂**:数字 + 类比 + 业务影响(例:"5-10 分钟 → 10 秒")
- **架构师可懂**:架构图 + 技术选型(例:"Nebula 三机房 + ClickHouse")
- **ML 工程师可懂**:具体指标和算法(例:"BM25+ColBERT, Recall@5≥70%")

写每页时**先确定目标读者层级**,只用对应级别的术语。

### ASCII 草图节制

多轮迭代时,**草图描述用文字结构**(标题 + 分点列表)而非 ASCII 框图。ASCII 框图只在**关键节点**用一次(最终敲定方案)。要看视觉效果直接生成 pptx 截图给用户,比 ASCII 草图准 100 倍。

## 设计原则

### 1. One Idea Per Slide

每页只传达一个核心信息，用视觉元素辅助表达，不要堆砌内容。

### 2. Visual Hierarchy

信息分层，引导观众视线：

```
Title（最大）
  ↓
Key Point（突出）
  ↓
Supporting Details（较小）
  ↓
Source / Footer（最小）
```

### 3. Rule of Thirds

将关键元素放在九宫格交叉点上：

```
┌───┬───┬───┐
│ 1 │ 2 │ 3 │
├───┼───┼───┤
│ 4 │ 5 │ 6 │  ← 在交叉点放置
├───┼───┼───┤    核心视觉元素
│ 7 │ 8 │ 9 │
└───┴───┴───┘
```

### 4. Contrast 制造重点

- 大 vs 小
- 深色 vs 浅色
- 彩色 vs 中性色
- 图片 vs 文字

### 5. Alignment 制造秩序

- 统一边距
- 相关元素对齐
- 建立隐形网格

## Tips for Better Slides

1. **消灭要点列表** -- 用视觉元素替代 bullet points
2. **每页一个数字** -- 让数据更有冲击力
3. **满幅图片** -- 图片铺满整页，文字叠加其上
4. **深色背景** -- 在暗光会议室中更醒目
5. **统一图标风格** -- 全程使用同一套图标集
6. **有目的地动画** -- 支撑叙事，不做装饰
7. **留足边距** -- 内容不要贴边
8. **投影仪测试** -- 屏幕上的颜色和投影差异很大

## Screenshot Review

当用户发来 PPT 页面截图请求检查时，按以下流程执行。

### 检查项

1. **元素重叠或遮挡** -- 形状、图片、文本框之间是否存在覆盖
2. **文本溢出或截断** -- 文字是否被框体边界切断、省略号、或消失
3. **间距不均匀** -- 元素间距 < 0.3" 或边距 < 0.5" 时标记；相似元素间距应一致
4. **对齐偏差** -- 列、行或相似元素是否存在肉眼可见的未对齐
5. **低对比度** -- 文字/图标与背景对比度不足，难以辨认
6. **文本框过窄** -- 导致文字过度换行，单词断裂
7. **残留占位符** -- "Click to add text"、"Lorem ipsum" 等未替换内容

### 输出格式

逐页列出发现的问题，格式：

```
### 第 N 页

- [问题类型] 具体描述（位置、涉及元素）
- [问题类型] 具体描述
```

即使是微小问题也要报告，不要省略。

### 核心原则

假设截图中一定存在问题。你的任务是找到它们，而不是确认"看起来没问题"。
